# R02：修改前健康基线

用户于 2026-09-09 确认，仅纳入 R02。归属 HD-BST-002，沿用 L2 门槛，不新增计分项；与 HD-HYG-001 的退出检查配合，不能把同一缺口重复计分。最初纳入目录 0.3.0，当前版本与证据门槛见 [工作流](workflow.md)；来源注册表 0.2.0。旧目录报告必须重新判断。

## 需要检查的约定与证据

每个独立修改任务首次编辑前，在实际目标 Worktree 选择并执行相称、已获授权的检查。记录任务、基线提交、工作树状态、检查选择理由、精确命令、工作目录、运行时间、退出状态/实际结果、已有失败和未验证范围。仅有命令、配置、旧 CI 绿灯或事后结果不能替代该任务的修改前基线。

完成后在可比较的环境和检查范围下区分已有失败、本次新增失败及已修复失败。基线有已知失败不等于全绿：明确说明失败项、对当前任务的影响和继续工作的依据。新增失败或验证入口不可用不能靠旧基线豁免；不自动扩展任务去修复无关历史问题。环境、输入、检查范围或工作树变动影响可比性时，说明限制，不能宣称“没有回归”。中途补测应标为补测，不能追记成首次编辑前已验证。

检查按变更表面选择：文档修改可用相关结构/链接检查，代码修改使用相关测试，涉及应用启动或用户流程才考虑相应运行验证。不强制每次跑所有检查、启动应用或安装依赖。纯只读任务没有修改前/后比较；但 Doctor 只读运行不等于被诊断仓库的开发流程不适用。HD-BST-002 原有框架可用性检查仍按仓库实际情况适用。

## 状态判定

| 状态 | R02 判定依据 |
| --- | --- |
| 已满足 | 规则完整，适用任务有实际修改前记录，验证入口可用，已结束任务还有可比较的退出结果；未结束任务不预先判定退出已通过 |
| 部分满足 | 有规则、命令或部分运行证据，但缺任务关联、修改前基线或失败对照等关键内容 |
| 缺失 | 在完整允许范围内没有基线约定或相关记录；不是仅因静态扫描未执行测试就判缺失 |
| 冲突 | 声称先检查后修改却有相反记录，掩盖失败，或把事后运行当成修改前记录 |
| 无法验证 | 缺权限、环境、依赖或可访问的关键结果；不得因无法执行而记作已通过或不适用 |
| 不适用 | 当前任务确无文件修改时，R02 的前后对照不适用；整个 HD-BST-002 只有符合其目录适用性时才排除计分，例如无自动验证能力且有明确人工验收方式 |

Python 仅收集静态事实，不执行测试或推断语义状态。命令声明的 `executed=false`、未读正文和截断内容不能视为运行成功；Agent 应引用可读记录，并交代真实性和范围限制。写出规则/模板也不自动把状态变为已满足。

## Doctor 自身补强时

1. 只读诊断不执行项目命令、不写基线文件。选中 HD-BST-002 后，默认生成规则或基线模板供统一预览，不自动提供新的命令执行器。
2. 准备获授权的新 Worktree 后、最终文件预览前，说明相称的基线命令、目录和副作用并按当前用户授权执行。测试也可能产生文件或访问外部系统；命令写在仓库中不是授权。没有运行条件时保留无法验证状态，说明能否仅继续用户批准的文档补强，不声称业务实现已通过。
3. 基线检查后重新取证，再进行最终差异预览，以免缓存或工作树变化使旧摘要失效。只记录到外部临时结果或会话输出；若用户选择持久化任务基线记录，该文件也必须列入完整差异预览，不能提前写入目标仓库。
4. 确认后只应用预览内容，执行已授权的退出检查，对照实际失败项，而不是只比较通过数量。按 [Git 工作流规则](git-workflow-policy.md) 完成任务范围内提交，再复诊。检查范围有变化时解释影响；本规则不授权 R03 的验收差异检测器或其他研究候选。

## 可选的基线记录模板

仅在用户选择持久化记录并确认差异后写入；使用仓库已有任务记录位置，不要求一任务一新文件。下列字段由真实观察填写，不能把占位内容当证据。

| 字段 | 应记录内容 |
| --- | --- |
| 任务与作用域 | 任务标识、修改范围、非目标 |
| 修改前身份 | Worktree、提交 SHA、工作树状态、运行时间 |
| 检查 | 选择依据、精确命令、目录、环境、授权与副作用 |
| 修改前结果 | 退出状态、已有失败明细、结果位置、未验证范围 |
| 退出对照 | 对应运行身份和时间、已有/新增/已修复失败、可比性限制 |
