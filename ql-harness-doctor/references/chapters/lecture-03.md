## 忠实摘要

### 核心结论

Agent 稳定可访问的世界主要是任务输入、仓库文件和工具输出。因此，影响开发决策的产品、架构、运行、验证和状态知识必须进入仓库，并放在容易发现且接近作用域的位置。目标不是增加文档数量，而是降低知识可见性缺口、发现成本和知识衰减。

### 关键概念

- **仓库即规范/系统记录**：仓库内信息是 Agent 的权威事实来源。
- **知识可见性缺口**：关键知识中未进入仓库的部分。
- **全新会话测试**：新 Agent 能否只靠仓库回答系统是什么、如何组织、如何运行、如何验证、当前做到哪里。
- **发现成本**：找到一条关键信息所需的上下文和探索成本。
- **知识衰减率**：仓库知识随代码演进而过时的速度。
- **状态 ACID 类比**：用原子性、一致性、隔离性、持久性思考 Agent 工作状态。

### 失败模式

- 架构约束散落在聊天、工单、外部文档和个别人脑中。
- 根文档存在，但无法回答产品目的、架构、启动、验证或当前状态。
- 大而远的中心文档代替靠近代码的作用域文档。
- 文档没有随代码变化，过时信息被误当作权威事实。
- 多 Agent 共享同一状态文件而没有隔离。

### 实践建议

- 用短入口文件提供项目地图，并把详细规则放在对应模块附近。
- 保持知识最小但完备；只有会改变 Agent 决策的内容才进入 Harness。
- 将文档更新与代码变更绑定，在评审或 CI 中提醒检查。
- 使用 Git 提交、验证谓词、分支或独立状态文件提供原子性、一致性、隔离性和持久性。
- 用全新会话测试验证信息是否真正可发现。

### 重要限制与反例

- “唯一事实来源”不要求复制所有外部材料；仓库可以存放经过维护的结论和权威链接。
- 文档越多不等于可见性越好；重复和过时信息会制造冲突。
- 用固定文件名只能发现候选证据，不能证明内容仍然准确。

### 可能状态判断

- **已满足**：五类问题均能从明确、相互一致的仓库证据回答。
- **部分满足**：信息存在但入口不可发现、分散或缺少维护责任。
- **缺失**：关键决策只能从仓库外获得。
- **冲突**：多个位置对同一事实给出不同答案。
- **无法验证**：文档存在，但无法判断是否与当前代码一致。
- **不适用**：单模块仓库可不要求模块级文档；单 Agent 不要求并行状态隔离。
